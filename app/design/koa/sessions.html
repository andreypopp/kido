koa — sessions inside the page

/resume opens a session picker in the page, /new starts a new session; both through pi's RPC (switch_session, new_session). The picker is a card in the dock above the field, where an extension's dialog card sits, so the transcript stays visible behind it and the keys are the dialog's: ↑↓ move, ↩ open, ⎋ close, ⇥ switches the scope. The composer under it is inert while it is open.

1 · The picker

A search field at the top (focused; the typed text filters name and first message, fuzzy as pi's selector does), and at its right a two-part scope, this folder / all, ⇥ switches it; this folder is the default. Rows, newest first: the name in the foreground (the first message when the session has no name), with current after the open session's name and, in all, the folder after the name in the faint tone; the first message under it, muted, ellipsized; at the right, the date (time for today, date otherwise) over the message count, in the faint terminal font. Eight rows visible, the list scrolls. The current row is the one the open session is, so ↩ on it does nothing.

2 · Search, and empty

Left: side typed, two matches. Right: a folder with no sessions: one line, "no sessions in this folder", with the hint "⇥ all folders" under it; the same card with "no match" when the search finds nothing.

3 · During and after a switch

On ↩ the card closes, the transcript empties, the field is inert with the placeholder "loading…" and the state cell reads loading (left). When pi answers, the session's transcript is in place, scrolled to its end, and one notice line at the end says "session: name · 212 messages" (right); the foot shows the session's model and context. /new is the same with an empty transcript and the notice "new session". The queue, if any, is gone with the old session; the draft in the field is kept.

4 · While a turn or a ! command runs

/resume and /new while pi works, or while a ! command runs, first ask: pi's confirm dialog in the dock, "Switch session?" with "koa is working on a turn; it will be aborted." (or "a command is running; it will be cancelled"), ↩ Switch, ⎋ Cancel. Switch aborts (pi's abort, or abort_bash) and then opens the picker or starts the new session; Cancel leaves everything as it was.
