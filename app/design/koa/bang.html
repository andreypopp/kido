koa — ! runs a command

As in pi's TUI: a message that starts with ! is not a prompt. koa runs it through pi's bash RPC command, and the output goes into the session as a bashExecution message, which pi gives the model before its next turn. !! runs it the same way with excludeFromContext: the output stays in the session and the transcript, and the model never sees it. The composer shows the mode by its font: while the text starts with !, the field is in the terminal font. Nothing else changes in the composer.

1 · The composer in ! mode, and in !! mode

The whole text switches to the terminal font at the pane's font size the moment the first character is ! (a space after it is allowed; ! alone is the mode with no command, and Return does nothing). The ! is the accent, 600; for !! the pair is muted, because that run is quiet. The state cell of the foot reads run (or run, quiet) in place of idle, so the row says what Return does; the model, context and cwd stay. No tag, no badge, no border change. Completion: @ and / completion are off in this mode; path completion stays, because a command takes paths. Chips: an attachment cannot go with a command; a drop while in ! mode is refused with the usual line under the field ("a command takes no attachments"), and chips that exist when ! is typed stay but Return does not send while they exist (the state cell reads run in the error colour with "remove the attachments" as its tooltip).

2 · A command in the transcript: running, done, failed, cancelled, quiet

A user-run command is a line of its own kind, in the geometry of a run line, where it ran: a ! in the accent where a run has its chevron (a faint !! for a quiet run), the command in the terminal font in --fg (red when the exit is not 0, as a failed tool's name is), and at the right, in the time's place, the exit when it is not 0 ("exit 1", red) and the duration. The output is folded by default and opens on a click of the line, in a well like a step's output, capped at 260pt with its own scroll; while the command runs the line shows the spinner where the ! will be and the output streams open, in muted text that turns --fg when it ends. A cancelled run says "cancelled" in place of the exit, and keeps the output it got. Truncated output (pi's truncated) ends with "… full output: path" in the faint terminal font. The model's next turn can see the output of a ! run; nothing in the transcript says so. A !! run is the one marked: its faint !! says "not in the model's context" as its tooltip.

3 · While it runs, and while pi works

While a command runs and pi is idle, the field stays in ! mode with the text cleared, the placeholder "running… ⎋ cancels", and the state cell reads running 3s with the breathing green dot: Return sends nothing, Escape cancels the command (pi's abort_bash), and typing starts the next message as usual. While pi works, a ! message runs at once, as in pi (the session record waits for the turn's end; the line does not): its line is appended at the end of the transcript, under the streaming reply, and streams there while the reply goes on above it. The state cell stays working 12s, the turn's state; the command's own spinner says it runs. The field returns to the working placeholder "Steer koa…". Escape then cancels the command first; a second Escape aborts the turn. Right: both running.

Typing !git status while pi works is the ordinary ! mode: the font switches, the state cell keeps working because the turn is the session's state, and Return runs it.

4 · Tab completes, from bash

In ! mode Tab asks bash (where the command runs: the Mac, or the runtime of a routed agent) for the completions of the word at the caret; nothing completes as you type. The answer is plain words, so there are no kinds. The behaviour is a shell's: one match completes the word inline, with a space after it or a / after a directory, as bash reports it; several matches first insert their common prefix inline, then open the list: the / popup's geometry, rows in the terminal font in the foreground, no detail or kind column, eight visible, bash's order. A second Tab or ↓ moves, ↩ or Tab accepts, ⎋ closes, and typing closes it and narrows the next Tab. The list never opens by itself. Left: !make ver after one Tab: verify was the common prefix of five targets, inserted, and the five are listed. Right: no completions: the state cell reads no completions for 1.5 s in place of run and nothing else moves; a request slower than 150 ms shows completing… with the spinner in the dot's slot until it answers (Tab waits, typing cancels). Over the cap (200 words) the last row is "… 184 more, type to narrow" in the faint tone, not selectable.
