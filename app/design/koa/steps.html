koa — the bare dots row stays; agent messages and jobs as steps of the run

Two requests of 2026-11-20, on the shipped language (unified rows, v3 padding, 12pt radii, the border depth; the working dots of 2026-11-15). 1: once a turn renders the bare dots row, no frame before the turn's end removes its space: the row is always the last element, a run that starts turns the same node into its line, text appends above it. 2: messages to and from agents, reports and async_bash jobs are steps of the tool/thinking run, not rows: the folded run names them in its summary, an open run lists them as steps, and a step opens to the whole message or the job's output. The user's own messages, the reply's prose and koa's own notice rows stay rows.

1 · The bare dots row: one turn, frame by frame

The same turn in four frames. The bare row appears under the user's message and is the last element from then on. When the agent's first tool call starts, that node becomes the run's line (same height, same spacing: nothing is reserved and nothing moves). When reply text streams after the run, the text and a bare row append below it: growth, never removal. The turn's end removes the bare row in one frame, the only time the content moves up. Click a run line to open it.

b · a thinking block starts: the same node is now the run's line

c · text streams after the run: the text and a bare row append below

d · the turn ends: the bare row goes, once

e · a second run after the text: the bare row of c became its line; the text keeps its place

2 · Agent messages and jobs as steps of the run

Left: a turn in which the agent spawned an implementer, waited for its report, started a verification job and read its end: one run, folded, then the reply; a second turn with a refused message. Right: the same first run open: thinking, the spawn as a step ("task to @impl", the message's first line as a tool shows its command), bash, the report as a step opened to its whole text (prose, no cap), the job's start and end as steps ("job make-verify", the event where the detail goes, red for a failure, the output as a bash well with the "open" link to the job view), and the refused message in red. The folded summary names them in order of first occurrence, "to @impl x2" for a repeat, the failed one red; no counts, no icons. Below: an item outside a turn (a report while idle) starts a new folded run row at the end, one new item for the divider; the next item joins it.
