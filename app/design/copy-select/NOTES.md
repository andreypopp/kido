# Copy mode: selection, context menu and prompt boxes — approved design (0.26.0 plus the floating, multi-box revision)

Open `mockup.html` through the design preview server (`python3 -m http.server 8765 --bind 127.0.0.1` from `app/design`, then http://127.0.0.1:8765/copy-select/mockup.html). Self-contained, no network, nothing is sent. Controls select the selection gesture, the stage (menu and every box state), the surrounding chrome (COPY pill, hover toolbar, find open with the toolbar below), the number of boxes (one; two with the second in the other pane, unfocused; two at one anchor, offset), the layout (box below the selection, selection near the bottom so the box opens above, a floating pane under the box, a narrow 320pt pane) and the theme. Click a box to focus and raise it; click the terminal to focus it and leave the boxes open. Right-click the pane, press ⌘O or `p` for the flow; drag the box by its header; Enter sends (simulated: the box closes, the selection clears), Escape cancels. The panel under the window shows exactly what would be sent; the gallery renders every box state in light and dark.

Decided by the user on 2026-10-18 from `/tmp/kido-copy-select-plan.md` (all recommendations) plus the designer's fixes listed below. Reuses the pane capsule style from `app/design/pane/NOTES.md` (opaque theme-background fill mixed 8% toward foreground, 0.5pt foreground-12% edge, 0.5pt white-12% inner top highlight, 6/18pt black-20% shadow, 12pt radius, 26pt IconButtons with 15pt symbols).

## 1. Mouse selection in copy mode (app-side, never forwarded to Ghostty)

- Left press places the copy cursor (a press on a selection drops it); drag selects from the press cell; double-click selects the word, triple-click the wrapped line; a drag after double or triple extends by word or line; Shift-click extends the current selection to the clicked cell in the current mode. Keyboard motion continues from a mouse-placed cursor; `y`/Return copy a mouse selection. Drag beyond the grid autoscrolls the frozen viewport within loaded rows only.
- The mouse never enters copy mode from a normal pane; outside copy mode Ghostty's own selection stays as it is. Both feed the same menu and box through `read_selection`.
- Selection color: `controlAccentColor` at 35% (dark) / 28% (light) behind the cells, 2pt radius on run ends, text unchanged; the copy cursor keeps its hollow block.

## 2. Context menu (native NSMenu, built fresh per click)

- Trigger: right-click or Control-click on a pane that has a selection, in copy mode or not. A right-click outside the selection, including on empty cells, keeps the existing selection and opens the menu for it; with no selection it selects the word under the pointer first (in copy mode, in `v` mode); with no text under it and no selection, nothing opens.
- Items, in order: **Copy** (⌘C) and **Prompt with Selection…** (⌘O; `p` also in copy mode). The prompt item reads **Prompt…** when the pane has no selection. Nothing else: no Select All, no Exit Copy Mode, no submenu, no ⌘⇧P or ⌘⇧↩.
- ⌘O works everywhere, with or without a selection, including copy mode with no selection; it never beeps. With a selection it opens the box as the menu item does. Without one it opens the **no-quote box** (section 3a). It is the key equivalent of the Edit menu item, which reads **Prompt with Selection…** ⌘O when the focused pane has a selection and **Prompt…** ⌘O otherwise; nothing in Kido.app or Ghostty's defaults uses ⌘O. `p` stays the copy-mode key and still needs a selection.
- Copy behaves as today: in copy mode it copies and exits copy mode; outside it copies Ghostty's selection and keeps it.
- Prompt with Selection… is always enabled when a selection exists; availability of a target is shown inside the box, because candidates are known only after the resolve request.
- Mouse-reporting programs receive the right-click unless Shift is held; a user `right-click-action` other than `context-menu` hides the menu (documented, not worked around).

## 3. Prompt box (inline capsule in the pane)

- **A floating box, not a pane capsule.** The box is a lightweight floating view inside the Kido.app window (a subview of the window's terminal area, not a separate NSWindow or NSPanel), so it may cross pane borders. Same capsule chrome: theme-background fill, 0.5pt edge, 12pt radius; the shadow is the float's (black at 40%, y 14, blur 40) rather than the capsule's, because it sits above content. Z-order: above every pane, divider, floating pane, hover toolbar, find capsule and COPY pill; below sheets and menus. Floating panes behind it stay live and are not dimmed.
- **Width.** 560pt, reduced to the terminal area's width minus 16 when the window is narrower. The height follows the content (one to five text lines, quote, rows).
- **Opening position.** Just below the selection: top = the last selected row's bottom + 6pt, left = the first selected cell's x. If the box would not fit below (bottom edge beyond the terminal area − 8), it opens above: bottom = the first selected row's top − 6pt. If it fits neither way (a very tall selection in a short window) it sits at the terminal area's bottom edge, covering the selection's lower rows. The left edge is clamped so the whole box stays within the terminal area with an 8pt margin on every side. The terminal area is the window below the 52pt toolbar band, including every pane, whichever pane the selection is in. The COPY pill, the find capsule and the hover toolbar stay exactly where they are; opening the box closes nothing.
- **Dragging.** The header row and any area that is not a control (field, quote, buttons, popup) drag the box; the cursor is the open hand over those areas, the closed hand while dragging. The drag is clamped to the terminal area with the same 8pt margin. The position is not saved: the next box opens at the selection again.
- **Several boxes.** Every ⌘O, `p` or menu choice opens a new box for that selection, with its own captured quote, picker, text and state; opening one never closes another. A box opened at an anchor already occupied by a box's top-left corner (within 4pt) is offset by +16, +16 from it, repeated until free, then clamped. There is no cap on the number of boxes.
- **Independent of copy mode once open.** Exiting copy mode, selecting elsewhere, scrolling, new output, layout changes, zoom and unzoom leave every box where it is (anchored to the window, not to the text; the quote was captured at open). Once open a box is not tied to the selection at all: the quote is text captured at open, and later selection changes, clears or a copy-mode exit do not touch it. Its only link is to the source pane, which is used to resolve the agent candidates. A box closes only on × or Escape while it has focus, or on successful delivery.
- **Source pane gone** (closed, or its window killed): the box stays open and can still send. It keeps the candidates it already resolved; the popup's detail reads "in window app (pane closed)" and the status "Source pane closed; agents resolved earlier stay available." in secondary. Candidates are not re-resolved (there is no pane to resolve from). A send to a target that is gone by then fails as *invalid* ("no such pane") and the box stays with its text.
- **Owned by the tmux session.** A box belongs to the session it was opened in. Switching windows within that session keeps every box visible at its place (it is anchored to the terminal area, not to a pane). Switching to another session hides them; returning to the session shows them again at the same positions. Killing the session closes them. Window resize re-clamps each box into the terminal area.
- **Focus and stacking.** The newest box takes key focus and sits on top. Clicking a box focuses it, raises it above the other boxes and moves focus to its field; clicking the terminal focuses the terminal and leaves every box open and in place (unfocused boxes show no ring, slightly lighter chrome through the missing ring only). Escape in a focused box closes it and returns focus to the pane it came from, in copy mode if that pane is still in copy mode, otherwise to the live pane. There is no keyboard cycling between boxes; clicking a box is the way to focus it.
- **Rows, top to bottom.**
  - Head, 32pt: the **target popup** at x 3, 26pt tall, 8pt radius, 12pt text, hover fill label 12%, chevron: "Prompt **@name** in this window". It is always a popup: agents in the pane's window first, then the rest of the session (with window name), the closest (first same-window) preselected; each item shows the status dot, title and pane id. While the resolve request is in flight it reads "Resolving…" (secondary, inert). With no candidates the popup is absent and the head reads "No agent in this window or session" in secondary, with the field and Send disabled. Spacer, then × Cancel (26pt IconButton, tooltip "Cancel (Escape)", accessibility label "Cancel").
  - Text: an NSTextView without bezel, 13pt system, 18pt lines, 11pt inset, placeholder "Ask about the selection", grows from one to five lines (90pt) then scrolls. Enter sends; Shift-Enter inserts a newline; Escape cancels.
  - Quote, below the text: the selection's a condensed view in 11pt monospace secondary with a 2pt accent-60% left bar: up to three lines are shown whole; a longer selection shows its first line, an italic "⋯ N lines" (the count of hidden middle lines) and its last line; each shown line is truncated with an ellipsis. Captured when the box opens (`read_selection`), not at Send; the full captured text is the quote's tooltip. Not editable.
  - Foot, 32pt: status text (11pt) at the left, spacer, the hint "↩ send · ⇧↩ newline" in secondary while idle, and **Send**: a 26pt accent-filled button with the arrow glyph (tooltip "Send (Return)"), disabled (label 14% fill) while the text is empty or no target exists.
- **Key loop and ring.** The text view is first responder on open; the box shows the accent focus ring (40%, 3pt) while the field has focus. Key loop: text, target popup, Cancel, Send. ⌘ chords typed in the field go to the field, not to the pane's copy-mode handling; ⌘O while the box is open does nothing.
- **Sending.** Text, popup and Send disable; status shows a 9pt spinner and "Sending to @name…". The request names the pane and the explicit target chosen in the popup.
- **Delivered.** The box closes, the selection clears, copy mode exits and the live pane is restored. No jump to the target.
- **Errors** (status in red under the field, text kept, verbatim kido message):
  - *Refused* ("@name is not accepting messages", inbox advertised but not accepting, nothing delivered): a **Retry** button next to the message; Send stays disabled until Retry or an edit.
  - *Delivery unknown* (socket error after connect): "Could not send: <error>. It may have arrived; not resent." with a **Copy Prompt** button that puts the composed text on the clipboard; Send is hidden for this composition, there is no Retry.
  - *Invalid* ("no such pane", "empty prompt", "pane %12 is not an agent"): the message only; Send re-enabled after an edit or a new pick.
- **Composed text**, exactly as delivered through the prompt RPC:

      <prompt text>:
      > line 1 of selection
      > line 2 of selection

  One trailing newline from line mode is stripped first; every remaining selection line, empty ones included, gets "> "; the colon is added unless the prompt already ends with ":".
- **Accessibility.** Box: role dialog "Prompt with selection". Popup: "Send to", pop-up button. Text view: "Prompt". Quote: static text "Selected text, N lines". Status: polite live region. Send: "Send prompt". Cancel: "Cancel".

## 3a. ⌘O without a selection (approved)

- **Placement.** The box opens just below the terminal cursor of the focused pane: top = the cursor cell's bottom + 6pt, left = the cursor cell's x; above it (bottom = the cell's top − 6pt) when there is no room below. Every other placement rule is the same: it crosses pane borders, is clamped 8pt inside the terminal area, and is offset +16, +16 from a box already at that spot. Dragging, session ownership, stacking, focus and closing are unchanged.
- **Appearance.** The same box without the quote block; the placeholder reads "Ask the agent" (my wording; "Ask about the selection" would be wrong without one): head with the picker and ×, the field, the foot with status, hint and Send. Height 35 + 2 + field + 35 (90pt with a one-line field; the field keeps its 2pt top gap).
- **Payload.** Exactly the typed text: no colon appended, no "> " lines. The composed-text rule of section 3 applies only when a selection was captured.
- **States and errors** are the picker, field, Send, resolving, no agent, sending, refused, unknown, invalid and pane-closed states of section 3, unchanged. The source pane is the focused pane at open; it resolves the candidates and stays the source if it closes later.
- The preview's Selection control has "None · ⌘O at the cursor": the box anchors to the caret, the quote is absent, the context-menu item reads "Prompt…", and the payload panel shows the text as typed.

## 4. Revision after 0.26.0 (user request)

⌘O added as the shortcut (menu item, copy mode and ordinary selections; beep without a selection). The box left the pane's bottom-left corner and became the floating, draggable, window-level box in section 3, opening below (or above) the selection, crossing pane borders, above floats, clamped to the terminal area, position not saved, closing when its pane closes or zooms, keeping focus with Escape returning to copy mode. Picker, quote, states and error kinds unchanged. Then the several-boxes decisions: boxes belong to the tmux session, survive window switches, are not tied to the selection after open, and stay sendable after their source pane closes.

Later the user approved ⌘O without a selection (section 3a). All questions of this revision are settled: ⌘O lives in the Edit menu; the quote is condensed (first line, ⋯ N lines, last line); a selection that fits neither way puts the box at the area's bottom; no cap on boxes; no cycle key.

## 5. Fixes the user accepted over the plan

Keep the find bar and the COPY pill while the box is open; × and a 26pt icon Send instead of text buttons; Enter sends and Shift-Enter inserts a newline; the menu item stays enabled and the box reports "No agent…"; the quote sits below the prompt with the full selection as its tooltip; a right-click on empty cells opens the menu for the existing selection; placeholder "Ask about the selection"; the popup is always shown (not only for several candidates). The error reply needs a kind the app can read, so refused, delivery-unknown and invalid render differently.
